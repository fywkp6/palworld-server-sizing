## 开服到底要多大机器

把 1GB～3GB 的解析峰值当成一笔固定开销，再去算游戏本体和余量，思路就清楚了。管理工具的说明文档里写得很直白：解析 `Level.sav` 会在短时间内使用约 1GB～3GB 内存，请确保运行环境有足够资源。这句话不是提醒你“最好多买点”，而是告诉你最低配的边界在哪。

举两个具体场景。

4 个人长期在线，机器上只跑游戏服务端，2核2G 能跑，但你没有余量做备份和远程管理。加一个面板上去，解析存档的那几秒就会把内存顶到上限。这种配置我建议直接用 2核4G，把面板和游戏放同一台，省掉一台机器的心。

8～10 个人，同时开着面板、自动备份、可视化地图，4核8G 是能舒服跑起来的档。人数再往上、据点建得多、帕鲁数量堆起来，内存占用会跟着涨，这时候 4核16G 比“先买 4核8G 再看看”更省事，因为中途升配虽然可以，但升配窗口期玩家是进不来的。

还有一个常被忽略的点：面板显示的数据不是实时的。默认每 120 秒检查一次存档同步，页面展示的是最近一次 `Level.sav` 解析结果，实际延迟还取决于游戏什么时候写盘。你看到的在线人数、帕鲁状态，都可能比游戏里慢上一两分钟，别拿它当排障的唯一依据。

## 端口：四个数字，只有一个该对公网开

装完服务端起不来，八成是端口没放行。默认值如下：

| 端口 | 用途 | 要不要对公网开放 |
| --- | --- | --- |
| 8211/UDP | 游戏本体，玩家连这个 | 要 |
| 8212 | REST API，面板靠它保存世界、平滑停服 | 不要 |
| 25575 | RCON，远程命令 | 不要 |
| 8080 | 管理面板网页 | 不要直接开，走隧道 |

安全要求写得很明确：不要把 8212、25575 或面板的进程控制接口直接暴露到公网。8212 和 25575 一旦裸奔，等于把服务器的管理权限挂在公网上等人扫。8080 是面板默认端口，可以用 `--port` 或环境变量 `PST_PORT` 改，优先级是 `--port` 高于 `PST_PORT`，再高于配置文件里的记录，最后才是默认 8080。

远程访问面板的常见做法是走隧道：隧道只连本机的 `127.0.0.1:8080`，路由器不用开端口，然后在隧道层再加一道身份验证，不能只靠面板自己的登录密码。手机在外面想看一眼服务器状态，这种方式比直接开 8080 安全得多。

## 装完怎么管：更新、备份、重启三件事

服务端跑起来只是开始，后面每周都会遇到的三件事，官方和管理工具都给了解法。

**更新**。SteamCMD 的 App ID 固定是 `2394010`，管理工具不接受自定义 SteamCMD 命令，只能按它的流程走：保存世界 → 备份 → 平滑关服 → 更新 → 重新启动，应用更新时要求手动输入 `UPDATE` 确认。更新失败时它会暂停守护并停在“更新失败”状态，不会拿着可能不完整的服务端文件反复启动。这个设计是对的，遇到更新失败先看日志、修 SteamCMD 或网络，别急着点重启。

**备份**。存档在 `Pal\Saved\SaveGames\0` 这一层。Windows 上社区流传的脚本示例是每 2 小时备份一次、最多保留 10 份，运行中的服务器会先调用官方保存接口再打包。Linux 侧更常见的是 tar.gz 加 CRON 每小时跑一次，或者用 systemd timer。备份频率按你的接受度定，但“只留一份、放在同一块盘上”不算备份，那只是复制。

**重启**。平滑重启的正确顺序是通过官方 REST API 保存世界、停服、等旧进程真正退出、再拉起新实例，中间不会同时跑两个服务端。崩溃守护要配崩溃循环保护：短时间内连续失败若干次就停下来，否则一个坏掉的启动参数能让服务器无限重启。管理员手动停服之后，守护程序不应该再把它拉起来，这条也要确认。

如果用的是带本地进程管理的面板，注意平台限制：Windows 是首要支持平台，Linux 和 macOS 能正常用管理功能，但点“启动本地 PalServer 进程”会返回 `unsupported platform`。Docker 部署的也不该用宿主机的 Windows 进程管理，应该继续走 REST API、RCON 或独立的 agent 去管游戏服。买机器之前先想清楚你要不要这个功能，别为了它多花钱最后发现用不上。

## 面板能替你做什么，不能替你做什么

开源的面板工具现在能做的事情不少：玩家、公会、帕鲁和背包数据查看，踢出封禁广播，可视化地图，白名单，定时 RCON，存档备份与备份管理，世界设置编辑，据点中文命名，全服库存聚合，还有 QQ 群机器人。世界设置编辑走固定路径 `<PalServer 工作目录>\Pal\Saved\Config\WindowsServer\PalWorldSettings.ini`，写入失败会回滚旧配置并只尝试一次用旧配置启动，密码字段只显示“已设置/未设置”，不回显原值。

有几条限制值得提前知道，省得你以为工具坏了：

配种农场的提醒依赖“连续两次成功存档快照”的蛋实例集合，所以会晚于实际产蛋时间，蛋种、进度、预计完成时间目前拿不到可靠数据，界面上会显示未知而不是编一个数字给你。玩家成长进度是只读解析，不同 Palworld 版本字段可能变化，没验证过的字段会显示“当前存档无法解析”，不会伪造为零。

首次访问面板必须创建管理模式密码，这个操作只能成功一次，第一个访问的人就是管理员。**这个密码不是游戏服务器的 `AdminPassword`**，两者别搞混。万一被别人抢先设置了，停掉面板、删掉 `config.db` 再重启就能重置，`pst.db` 里的业务数据不受影响。

安全设计上也做了限制：进程控制接口全部要求管理员 JWT；启动参数里带 `&`、`|`、`>`、`<`、`cmd.exe`、`powershell.exe` 会被后端直接拒绝；配置查询不会返回 RCON 密码、REST API 密码和 JWT。

## 哪些钱不用花

只想和朋友玩几个晚上，别买服务器。游戏内联机够用，或者找个现成的社区服进去玩，省下的钱够买好几份游戏。专用服务器的价值在“24 小时在线、存档不在某个人的电脑上、房主下线别人不掉线”，这三点你不需要，就不必为此付费。

1核1G 的机器不要拿来跑带解析的面板。省下的那点钱，会在第一次 OOM 之后全部还回去。

不需要远程管理、不需要看谁在线上、不需要改世界设置，就不必为面板预留那 1～3GB。纯游戏服 2核4G 能撑的人数和“游戏服 + 面板”在 4核8G 上撑的人数差不多，钱花在哪一档要自己算。

还有一类人不适合自己开：希望“开完就不用管”的。服务端要更新，更新会停服；存档要备份，备份要占盘；MOD 和版本一升级就可能出兼容问题。这些工作量不大，但确实存在。

## FAQ

**32 人上限是真的吗？**

2026 年 10 月的一份第三方教程写着“最多 32 名玩家”，但这个说法没有在官方文档里核验到。另一份 2024 年 1 月的社区脚本示例里，启动参数写的是 `-players=80`，那只是示例参数，不是官方上限。开服前按当前服务端版本的官方文档和启动参数确认，别把脚本里的数字当成标准答案，也别把某个第三方教程的数字当成硬限制。

**面板数据为什么不实时？**

默认每 120 秒检查一次存档同步，页面显示的是最近一次 `Level.sav` 解析结果，不是内存里的实时状态。同步间隔可以在配置中心调，但最终延迟还是取决于游戏什么时候写盘。

**换机器怎么迁移？**

先停服。必须带走的是 `Pal\Saved` 整个目录，存档本体在里面。如果你在用面板，`config.db`（配置和管理员凭据）和 `pst.db`（业务数据）一起带走能少配一遍。新机器上配置里包含的路径要重新指一次，指完再启动服务端。

**能不能跨平台联机？**

专用服务器是跨平台联机的常见做法，但具体哪些平台能进取决于当前服务端版本和参数配置。开服之后先让不同平台的朋友各试一次，确认都能进再接其他人。
